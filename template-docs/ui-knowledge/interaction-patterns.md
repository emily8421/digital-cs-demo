## 1. 模式清单

### PAT-INT-001｜键盘焦点与焦点环

- **类型与维度**：Pattern / 可访问性与包容性、组件与表单行为
- **要解决的问题**：键盘用户无法定位当前操作位置，或无法仅用键盘完成操作。
- **建议**：所有可交互元素可达键盘焦点；焦点可见（焦点环）；焦点顺序符合阅读与操作流；不依赖鼠标悬停传达可交互性。
- **适用条件**：所有 Web UI（A 级基线）；尤其表单、工具栏、自定义控件。
- **不适用条件**：纯展示内容、装饰元素（应 `aria-hidden`）。
- **行为契约**：`Tab` / `Shift+Tab` 遍历可达元素；焦点环可见且与背景对比度 ≥ 3:1；动态插入元素显式管理焦点；模态对话框焦点陷阱并在关闭后归还焦点。
- **视觉信号**：焦点环颜色 / 厚度与背景对比；禁用元素不参与 Tab 且视觉置灰。
- **来源**：`SRC-A11Y-001`（WAI-ARIA APG）、`SRC-A11Y-002`（WCAG 2.2）
- **证据等级**：A
- **状态**：reviewed（2026-08-13）

### PAT-INT-002｜表单校验与错误恢复

- **类型与维度**：Pattern / 组件与表单行为、状态反馈与恢复、内容设计
- **要解决的问题**：用户填错后不知错在哪、如何改，或提交失败后已填内容丢失。
- **建议**：客户端即时校验 + 服务端提交校验；错误明确指字段、以用户能直接理解的语言说明原因、给修复路径；提交失败不清空表单。
- **适用条件**：表单密集场景（注册、下单、审批、多步表单）。
- **不适用条件**：单字段搜索框（即时反馈即可，无需完整错误恢复流程）。
- **行为契约**：失焦或输入时校验；错误态标 `aria-invalid` 并用 `aria-describedby` 关联错误文案；错误文案置于字段旁或上方；保留用户已填值；服务端错误回到表单并定位首个错误字段。
- **视觉信号**：错误用颜色 + 图标 + 文字三重表达（不只靠颜色）；必填项标记一致。
- **来源**：`SRC-DS-001`（GOV.UK Design System）、`SRC-DS-002`（USWDS）
- **证据等级**：B
- **状态**：reviewed（2026-08-13）

### PAT-INT-003｜加载 / 空态 / 错误状态完整性

- **类型与维度**：Pattern / 状态反馈与恢复
- **要解决的问题**：系统变化（加载、无数据、失败）无反馈，用户误以为界面无响应或自己操作出错。
- **建议**：每个数据驱动视图都设计加载、空、错误三态；空态给引导动作，错误态给重试或备选路径。
- **适用条件**：列表、详情、搜索结果、仪表盘、异步数据视图。
- **不适用条件**：纯静态内容。
- **行为契约**：加载 → 延迟 > 100ms 才显示骨架 / spinner（避免闪烁）；空 → 说明原因 + 主行动入口；错误 → 原因 + 重试 / 备选；恢复后回到原视图与滚动位置。
- **视觉信号**：骨架占位与最终布局形状一致；空态插图克制，不抢占主要内容视觉重心。
- **来源**：`SRC-DS-001`、`SRC-DS-002`
- **证据等级**：B
- **状态**：reviewed（2026-08-13）

### PAT-INT-004｜撤销与防误操作

- **类型与维度**：Pattern / 状态反馈与恢复、交互流程
- **要解决的问题**：误删 / 误提交后无法挽回。
- **建议**：破坏性操作前确认，或执行后给撤销窗口；删除走软删除 / 回收；批量操作支持撤销。
- **适用条件**：编辑器、邮件、文件管理、批量操作等可逆场景。
- **不适用条件**：不可逆的财务终态、法律生效操作——这些应强确认（二次输入 / 显式确认），而非依赖撤销。
- **行为契约**：破坏性操作 → 确认对话框说明后果，或执行后撤销 toast（5-10 秒）；撤销恢复原状态；不可逆操作要求二次确认。
- **视觉信号**：破坏性按钮区分（颜色 / 文案）；撤销 toast 醒目且可点。
- **来源**：`SRC-DS-001`；成熟产品观察（多案例一致）
- **证据等级**：C
- **状态**：reviewed（2026-08-13）

### PAT-INT-005｜渐进披露与逃生路径

- **类型与维度**：Pattern / 信息架构与导航、交互流程
- **要解决的问题**：选项 / 信息过多导致信息过载，或层级太深难以定位当前位置与返回路径。
- **建议**：按需展开次要选项（折叠面板、二级菜单、高级选项）；始终保留返回 / 面包屑 / 搜索等逃生路径。
- **适用条件**：设置页、复杂表单、多层级导航、数据密集界面。
- **不适用条件**：核心流程步骤——关键路径不应被藏起来。
- **行为契约**：展开 / 收起状态在会话内持久；深层页面提供面包屑 / 返回；大规模信息架构提供搜索、目录树、经典路径作为逃生舱。
- **视觉信号**：展开指示器（如 ▸ / ▾）；当前层级高亮。
- **来源**：`SRC-DS-001`、`SRC-DS-002`
- **证据等级**：B
- **状态**：reviewed（2026-08-13）

### PAT-INT-006｜AI 建议纠错与人工接管

- **类型与维度**：Pattern / 信任数据与人机协作、状态反馈与恢复
- **要解决的问题**：AI 生成内容或建议，用户无法判断对错、无法纠正、无法接管。
- **建议**：AI 输出明确标注来源（非既定事实）；提供编辑 / 拒绝 / 重新生成；高风险操作（发送、执行）保留人工确认；显示置信度或来源依据。
- **适用条件**：AI 生成内容、智能填写、自动化决策辅助。
- **不适用条件**：纯确定性计算（非 AI 模型输出）。
- **行为契约**：AI 输出 → 可编辑 + 可拒绝 + 可重生成；执行类 AI 动作 → 人工确认才生效；提供纠错反馈回路；AI 失败或低置信 → 降级为人工流程。
- **视觉信号**：AI 内容标记（图标 / 底色）；可编辑区域与只读区域区分；置信度暗示（不夸大）。
- **来源**：`SRC-HAI-001`（Microsoft HAX Toolkit）
- **证据等级**：B
- **状态**：candidate（2026-08-14；唯一来源 `SRC-HAI-001` 暂时不可用，待链接恢复并复核）

### PAT-INT-007｜可访问性语义与读屏

- **类型与维度**：Pattern / 可访问性与包容性
- **要解决的问题**：读屏用户无法理解页面结构、组件类型或状态变化。
- **建议**：使用语义 HTML 与 ARIA 角色；动态变化用 `aria-live` 通告；图标按钮带 `aria-label`；标题层级正确且不跳级。
- **适用条件**：所有 Web UI（A 级基线），尤其动态内容与富组件。
- **不适用条件**：纯视觉装饰（应 `aria-hidden`，不抢读屏焦点）。
- **行为契约**：landmark 角色（`nav` / `main` / `aside`）；状态变化（加载完成、错误、计数更新）经 `aria-live` 通告；表单 label 关联；提供跳到主内容链接。
- **视觉信号**：不适用（纯语义层，视觉不可见）。
- **来源**：`SRC-A11Y-001`、`SRC-A11Y-002`
- **证据等级**：A
- **状态**：reviewed（2026-08-13）

## 2. 使用说明

- 项目参考分析引用本文件模式时使用 `PAT-INT-NNN` ID；项目级采纳 / 调整 / 排除决定写入项目自己的 `docs/research/*frontend-ui-reference-analysis.md`，不回写本文件。
- 每条模式的「不适用条件」是防机械套用的关键；选用时必须先核对项目是否落入不适用场景。
- 行为契约字段可直接映射到 `docs/design/frontend-interaction.md` 的状态与交互描述，但项目实现仍须以正式交互设计为准。
- 新增模式须填全 §4.2 字段（`README.md`），状态默认 candidate；证据等级不得高于其来源能支撑的上限（`source-registry.md`）。唯一来源暂时不可用的模式不得升为 reviewed / core。
