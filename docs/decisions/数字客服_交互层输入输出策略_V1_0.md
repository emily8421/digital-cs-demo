## 三、技术边界（已核实，非待验证）

在制定输入输出策略前，须明确一条已被技术验证核实的硬边界：

**企业微信客户群内，系统自动回复外部客户的消息，在任何合规路径下均不可行。**

> 来源：DEC-7 原文"无对应官方接口——❌ 任何合规路径下均不可行，非局部限制，是平台层面硬限制"；02-srs.md、05-tech-spec.md、08-dev-plan.md 均记录"Sprint-0 已核实：客户群群内自动回复路径在企业微信标准能力下不成立"。

## 四、三类输入输出适配策略

基于渠道现状与技术边界，将所有渠道归入三种适配模式。后端引擎不变，仅交互层不同。

---

### 模式一：员工辅助工具

**覆盖渠道**：客户微信群 · 个人微信（1:1）· 门店到访

**核心逻辑**：客户不在知衍控制的系统内，AI 无法直接触达客户。由员工作为中间层，将客户消息转入系统，获取回复后自行发送。

**输入层**：
员工将客户发来的文字消息复制粘贴至 AI 对话框，或口头描述门店客户的问题。当前 H5 Demo 页面即可承载，无需新建入口。

**输出层**：
AI 返回产品参数、推荐理由、定制字段清单等内容，员工确认后以自己的名义发送给客户。客户侧对 AI 的存在完全无感知。

**合规状态**：无任何平台接入风险，不依赖任何官方接口审批。

**适用阶段**：当前阶段立即可用，无需等待任何前置条件。

**对客户的价值主张**：
> "你的员工用了这个，能更快、更准地回客户——新员工也能答出老员工的水平。"

---

### 模式二：平台直连自动回复

**覆盖渠道**：微信公众号 · 1688 旺旺消息

**核心逻辑**：客户在平台侧主动发起咨询，平台提供官方开放接口，系统可直接自动回复，不依赖员工转发。

#### 微信公众号

**输入层**：客户关注公众号后发送消息，平台通过 Webhook 推送至系统。

**输出层**：AI 处理后通过公众号消息接口直接回复客户，走官方 API，合规。

**注意**：客户需主动找到并关注公众号，与其现有习惯（微信群、直接加人）之间存在渠道迁移成本。接入前需先验证古晶客户中有多少人会走这个入口，否则接了也是空转。

**合规状态**：完全合规。V1.1 将其列为正式版第一期。

#### 1688 旺旺消息

**输入层**：买家在 1688 店铺发送旺旺消息，通过阿里开放平台 Webhook 接入系统。

**输出层**：AI 处理后通过阿里 API 回复买家消息。

**前置条件**：须先确认古晶是否真实使用 1688 作为询盘渠道，以及日均消息量是否足以支撑单独接入的开发成本。

**合规状态**：走阿里官方开放平台，合规。

---

### 模式三：邮件半自动化

**覆盖渠道**：外贸询盘邮件（英文为主）

**核心逻辑**：邮件属于异步渠道，不需要秒回。适合"AI 起草 + 员工确认 + 人工发送"的半自动模式，不追求全自动。

**输入层**：邮件转发至系统指定邮箱，或通过邮箱 API 读取外贸部收件箱中的客户询盘。

**输出层**：AI 识别询盘意图，起草中英文回复（含产品参数、交期、认证信息等），员工核对后以自己名义发送。

**适用场景**：
- 英文询盘理解与回复起草（WorkBuddy 文档标注为强烈推荐场景）
- 多语言版本批量生成（英/法/德/西/阿拉伯语）
- 海外客户催货、投诉邮件的语气把控

**前置条件**：外贸业务量须达到一定规模，开发接入成本才合算。需确认古晶外贸部每日邮件量级。

**合规状态**：邮件协议层面无平台限制，完全合规。

## 五、优先级建议

| 优先级 | 渠道 / 模式 | 启动条件 | 理由 |
|--------|-------------|----------|------|
| **立即启动** | 员工辅助工具（群 + 个微 + 门店） | 无，H5 Demo 已可承载 | 覆盖三条核心渠道，零合规风险，老板最易理解的价值 |
| **验证后推进** | 微信公众号 | 确认客户有走公众号的习惯 | 合规路径清晰，但渠道迁移成本未验证 |
| **调研后决定** | 1688 旺旺 | 确认古晶实际使用 1688 接收询盘 | 接入价值取决于真实流量，不可假设 |
| **按需推进** | 外贸邮件 | 确认外贸询盘量级 | 价值明确，但优先级低于内贸主渠道 |
| **明确不做** | 企业微信群内直接自动回复 | — | Sprint-0 已核实技术不可行，合规路径不存在 |
| **明确不做** | 个人微信自动化 | — | 知衍合规红线，永久排除 |
