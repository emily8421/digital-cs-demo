## 2. 优先级

- **P0（必须，进当前 P1）**：REQ-1 通道抽象+模拟器、REQ-2 单轮问答、REQ-3 标准 FAQ、REQ-4 留资、REQ-5+8 转交通知与路由、REQ-6 缺口检测、REQ-7 定时小结、REQ-10 转人工暂停、REQ-12 非文字处理。
- **P1（重要，P2）**：REQ-9 多轮引导、REQ-11 身份披露、REQ-13 知识回写、REQ-14 时效监控。
- **P2（可选/愿景·待技术验证）**：REQ-15 企业微信接入（先验后接）、REQ-16 订单进度（依赖外部系统）、REQ-17 售后规则推理（高风险 AI）。

> 注：本节「优先级 P0/P1/P2」是**功能重要性**口径；与 §3「阶段 P1/P2/愿景」是不同维度（前者＝重不重要，后者＝什么时候做）。二者不冲突：重要性 P0 的功能落在阶段 P1。

## 3. 阶段划分（⚠️ AI 建议 · 待人工确认）

> 这是阶段标签的唯一来源。确认/调整后，按 INIT-PROMPT §4 把标签同步到 04-09 / design-* / project-rules §1（**需求不变，只动标签**）。

### Phase1 / MVP —— 能独立演示核心价值的最小连贯子集

**核心价值命题**（来自愿景）：群里消息有人接了，该跟的已经分给该跟的人，经营者收到「今天要关注什么」的小结。

**纳入功能**：REQ-1、REQ-2、REQ-3、REQ-4、REQ-5、REQ-6、REQ-7、REQ-8、REQ-10、REQ-12（＋ REQ-15 验证通过后接入）。

**为何这样切**：
- 这些功能构成一条**端到端连贯闭环**：收消息(REQ-1) → 答得上的答(REQ-2/3) → 答不上的留资转人(REQ-4/5/6/8) → 经营者看小结(REQ-7)。缺任何一环都无法演示「消息被处理、跟进被分配」。
- 刻意**排除**高复杂度/高风险项（多轮状态机、售后推理、知识回写），它们是「让回复更好」的增强，不是「闭环成立」的前提。
- **由 P2 提至 P1 的两项**（经确认）：转人工暂停（REQ-10，人机协作正确性——人工接管后 AI 不抢话、不说法不一）与非文字处理（REQ-12，如实告知+提醒）——它们关乎演示与生产中「不出洋相」、且成本可控，故提至 P1。转人工暂停 P1 按**会话（群）级**实现，话题（thread）级精化留后续。
- 平台风险单独处理：REQ-15（企业微信外部群能力 ⚠️）作为 **Sprint-0 验证项**先行，通过则接入真实通道，未通过则 MVP 用内置模拟器(REQ-1)演示，**不阻塞核心价值验证**。

**演示什么（Demo 脚本）**：
1. 向模拟器投递一条产品参数问题 → 系统从知识库作答（REQ-2/3）。
2. 投递一条知识库未覆盖的问题 → 系统请客户留资并把缺口转交拍板人（REQ-6）。
3. 投递一条含手机号的满意度留言 → 系统记录留资并提醒售前跟进（REQ-4/5）。
4. 触发定时小结 → 经营者收到「当日消息量 + 需跟进清单 + 已分给谁」（REQ-7）。
5. 投递一条语音 → 群内如实告知无法识别并提醒员工查看（REQ-12）；标记会话「已转人工」后继续投递消息 → 系统不再自动回，直到解除标记（REQ-10）。
6. （若 Sprint-0 验证通过）切换为企业微信真实通道，重放 1–5（REQ-1/15）。

### Phase2 —— 优化扩展

**纳入功能**：REQ-9（多轮引导）、REQ-11（身份披露）、REQ-13（知识回写）、REQ-14（时效监控），以及 REQ-15 通过后的正式接入。
**定位**：让回复更准、协作边界更稳、知识可自增长、时效可观测。

### 远期愿景 · 待技术验证（高风险 / 依赖外部条件，不进当前阶段）

- **REQ-15 企业微信外部群接入能力**：Sprint-0 已核实——客户群群内自动回复路径**不成立**（群机器人仅内部群且只发不收、会话存档禁止用于自动回复；详见 `docs/sprint-0-wework-findings.md`）；需改替代通道（微信客服 / 智能机器人入外部群待官方确认），待人工选定后再细化。
- **REQ-16 订单进度转人工（售中）**：依赖外部订单/生产记录系统是否存在与可集成。
- **REQ-17 售后规则智能引导**：高风险 AI 推理（质保边界判定、安抚话术可控性），需技术验证后才细化口径。

## 4. 非目标（明确不做，防止范围蔓延）

本轮（P1）明确**不实现**：
- 不做多轮对话状态机 / 定制询盘逐项引导（→ P2）。
- 不做售后质保推理 / 退换结论 / 安抚话术生成（→ 愿景·待技术验证）。
- 转人工「AI 暂停」P1 仅做到**会话（群）级**；话题（thread）级精化留后续（非本轮）。
- 不做知识确认回写（→ P2）。
- 不做语音/图片/视频**内容**理解（永久非目标，见愿景补充说明 3）；P1 仅做**类型识别 + 如实告知 + 提醒人工**（REQ-12）。
- 不做订单/生产系统集成（→ 愿景）。
- 不做独立前端/员工后台（通知走消息通道；P2「知识确认」再评估轻量页面）。
- 不做对个人微信的非官方自动化（永久禁止）。
- 不追求「自动答所有问题」——答不上的明确走留资转人，**不编造**。
