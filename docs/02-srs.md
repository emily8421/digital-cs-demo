# 02 需求规格说明（SRS）

> 需求层 · 跨阶段稳定，**全量 REQ、不裁剪**（global-rules §8.3）。
> P1 REQ 写「可验证口径」（能说清怎样算满足）；P2/愿景 REQ 仅粗粒度，标「待该阶段细化」，不硬凑。
> 编号 REQ-* ↔ `docs/01-user-requirements.md` F-* 双向追溯；阶段标签取自 `docs/03-prd.md` §3（AI 提议·待确认）。

## 验证口径约定

- 「可验证」＝能给出**输入 → 期望输出**的客观判据，或一条可执行的测试用例。
- P1 每条 REQ 在 `docs/09-verification.md` 至少有一条验收用例。

## Phase1（Demo · 可验证口径）

### REQ-1 消息接入与归一化 `[F15a]` `[P1]`
系统经统一通道适配层接收一条客户消息，归一化为内部结构（会话/发送方/内容类型/原文/时间戳），并支持本地内置模拟器作为收发通道。
- 可验证：向模拟器接口投递一条文本消息，系统记录并能在内部会话视图读回该消息（字段齐全）；切换「模拟器通道 / 企业微信通道」不改业务逻辑（接口契约一致）。

### REQ-2 售前知识库问答（单轮） `[F1]` `[P1]`
对客户的产品参数/选型类问题，系统从知识库检索并生成一条贴合的作答；命中时作答，未命中时进入 REQ-6 流程，不编造。
- 可验证：预置知识条目（如「IP65 vs IP67 区别」）下，投递相关问题，系统返回的内容包含对应知识点；投递知识库未覆盖的问题，系统不返回编造参数而是走缺口流程。

### REQ-3 标准品采购引导（基础 FAQ） `[F3]` `[P1]`
对起订量/交期/付款方式等标准问题，系统返回带**具体数字**的答复（数字来自已配置的标准答案，非杜撰）。
- 可验证：配置起订量＝X 后，投递「起订量多少」返回含 X 的答复。

### REQ-4 询盘留资识别与记录 `[F4]` `[P1]`
系统从消息中识别出客户主动提供的联系方式（手机号为主），结构化记录并关联会话/发送方，供转交使用。
- 可验证：投递含合规手机号的文本，系统生成一条留资记录（含脱敏存储、原始会话引用）；无联系方式时不产生留资记录。

### REQ-5 人工转交通知（口语化） `[F5]` `[P1]`
对需人工跟进的事项，系统以**普通消息**形式发送口语化提醒（含事项摘要、客户/群标识、时间），员工侧无需登录系统；路由按 REQ-8 规则解析目标角色。
- 可验证：触发「售前询盘需跟进」时，通知送达售前角色并含摘要与客户标识；路由规则可配置（售前/技术/跟单/经营者各得其类）。

### REQ-6 知识缺口检测 → 留资 + 通知 `[F11a]` `[P1]`
当知识库无法作答（REQ-2 未命中）时，系统请客户留联系方式并告知将请同事确认，同时把该缺口问题转交拍板人/相关员工。
- 可验证：投递未覆盖问题，客户侧收到「请留资、将请同事确认」类提示，员工侧收到含该问题的缺口通知；缺口被记录为一条知识缺口条目。

### REQ-7 定时小结 / 日报 `[F12]` `[P1]`
系统每日在配置时间点向经营者发送小结：当日消息量、主要类型、自动处理情况、需人工跟进清单（含已分给谁）；可手动触发以便测试。
- 可验证：手动触发小结生成接口，输出含「消息总量 / 需跟进清单 / 分配对象」的小结文本；定时触发按配置时间执行。

### REQ-8 多角色业务路由（基础） `[F13]` `[P1]`
系统维护「场景 → 角色」路由规则，转交/提醒按规则分发；角色与对接人可配置。
- 可验证：配置规则后，不同场景的事项被分发到对应角色；修改规则后分发随之变化。

### REQ-10 转人工后 AI 暂停 `[F8]` `[P1]`
对话被标记为「已转人工」后，系统在该会话下对新入站客户消息**暂停自动作答/缺口流程**（仅记录，必要时提醒已接管员工），由人工经接口解除标记后才恢复自动回复。
- 可验证：将会话置 `handed_off` 后投递新客户消息，系统不产生面向客户的自动回复（outbound 无作答/缺口回包）；解除标记后恢复正常。
- 粒度说明：P1 暂在**会话（群）级**实现暂停；话题（thread）级精化为后续优化（群内多客户交叉本身是验证观察项，见愿景尾注 5）。

### REQ-12 语音 / 非文字消息处理 `[F10]` `[P1]`
对语音/图片/视频等非文字消息，系统识别类型后在群内**如实告知**（无法识别、请改文字或等待同事），并提醒对应员工查看；**不声称理解内容**（内容理解永久非目标，见愿景补充说明 3）。
- 可验证：投递一条 voice 消息，客户侧收到「无法识别语音，请打字或等待同事」类提示、员工侧收到查看提醒；系统不生成对该语音内容的作答。

> 说明：F15b 企业微信接入（REQ-15）经 Sprint-0 核实客户群群内路径**不成立**（见 `docs/research/sprint-0-wework-findings.md`），归入下「远期愿景·待技术验证」段；替代通道选定后再议。

## Phase2 · 优化扩展（粗粒度）

### REQ-9 定制询盘多轮引导 `[F2]` `[P2]` `[骨架·待细化]`
对堆叠多要求的定制询盘，拆分为多项逐条确认，逐项收集后整理为可核价摘要转交。
- 待细化：拆项策略、多轮会话状态机、未应答项的兜底、摘要模板。

### REQ-11 AI 身份披露边界 `[F9]` `[P2]` `[骨架·待细化]`
被问「是不是机器人/AI」时，以既定口径自然承认身份，不喧宾夺主。
- 待细化：触发识别、披露话术模板、与转人工的衔接。

### REQ-13 知识内容确认回写 `[F11b]` `[P2]` `[骨架·待细化]`
拍板人答复后，系统征询是否作为标准答案，**确认后**写入知识库；确认权与内容归属在客户方。
- 待细化：征询时机、确认交互（消息内 vs 轻量页面）、写入与版本/归属。

### REQ-14 响应时效 SLA 监控 `[F14]` `[P2]` `[骨架·待细化]`
保障无消息长时间未应答（口径 ≤30 分钟未回复），并对超时提示。
- 待细化：计时口径（客户消息→首次应答）、超时告警渠道。

## 远期愿景 · 待技术验证（高风险 / 依赖外部条件）

### REQ-15 企业微信外部群接入 `[F15b]` `[愿景·待技术验证]`
**Sprint-0 已核实（见 `docs/research/sprint-0-wework-findings.md`）：客户群群内自动回复路径在企业微信标准能力下不成立**（群机器人仅内部群且只发不收；会话存档禁止用于自动回复）。真实通道需改方案（候选：微信客服 1:1 / 智能机器人入外部群待官方确认），**待人工选定替代通道后再细化**。

### REQ-16 订单进度查询转人工（售中） `[F6]` `[愿景·待技术验证]` `[骨架·依赖外部系统]`
客户问订单工序进度时转跟单并附订单号/产品/客户标识。
- 待验证：依赖外部订单/生产记录系统是否存在、是否可集成；在确认集成来源前不实现「自动答进度」。

### REQ-17 售后规则智能引导 + 转人工 `[F7]` `[愿景·待技术验证]` `[骨架·高风险 AI]`
质保边界类售后：不直接给退换结论，先安抚转交并附购买时间/证据提示。
- 待验证：高风险 AI 推理——购买时间与质保边界的判定、安抚话术生成的可控性与一致性；需技术验证后才细化口径。
