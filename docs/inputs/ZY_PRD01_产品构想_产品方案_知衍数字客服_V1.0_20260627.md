# 知衍数字客服 · 产品构想
知衍启新 · 2026年6月

---

## 【封面】

**产品名称**：知衍数字客服

**一句话定位**：古镇老板靠微信做生意、靠人盯群——我们帮你把这件事交给AI。

---

## 【第2页】我们在做什么方向

### 古镇产业带的共同处境

基于古晶光电和乐式科技的一手调研，以及WorkBuddy照明行业培训的行业观察，古镇中小企业普遍面临同一个问题：

**靠微信做生意，靠人盯群。**

### 现有解法为什么落不了地

通用AI工具（腾讯云WorkBuddy等）已经进入古镇，但它们要求客户自备完整数据和规则——古镇中小企业做不到这一步，门槛太高，落地困难。

管理咨询公司能诊断问题，但老师一走就恢复原状，没有持续执行的机制。

目前没有针对这类企业的现成解法。

## 【第3页】目标客户是谁

### 画像特征

- 规模：10–200人，古镇产业带中小企业
- 生意方式：主要靠微信群维护客户关系，客户沟通、跟进、售后都在微信里
- 普遍困境：客户沟通量大，人手跟不上，夜间节假日有空窗；知识和规则没有系统沉淀，员工执行靠个人经验
- 老板的感受：想知道员工有没有在跟客户，但群太多，看不过来

### 已调研的典型客户

**古晶光电（灯具制造商）**
- 营收过亿，厂内群160个，客户微信群超1000个，销售各自维护，老板全部静音
- 张总原话：「盯已经盯不过来了。基本上等出了问题，谁过来告诉你，然后再去翻翻。」
- 已发生多次客户拍抖音事件，根源是售后规则不清晰、员工执行生硬

**乐式科技（智能家居解决方案商）**
- 项目型业务，服务品牌商和制造商，分两个阶段：方案开发（品牌商委托开发，量产版本发布后结束）、生产下单（品牌商或其指定供应商下单生产）
- 客户关心的问题：方案开发进度与配合事项（阶段一）、订单生产进度与交期（阶段二）、系统调试与维保响应（售后）
- 已自建微信群监控系统，漏回通知功能跑通运行超60天
- 明确提出三阶段数字客服需求：漏回通知 → 消息分类路由 → 知识库自主回复

## 【第4页】解决什么问题

### 痛点一：询盘漏回，客户等不住找别家

客户发了消息没人回，高峰期人手不够，夜间和节假日完全空窗。等老板发现已经晚了。

> 「盯已经盯不过来了。」——古晶光电张总

*产品型（古晶）：客户询盘无人及时回复；项目型（乐式）：品牌商咨询方案、供应商询问交期，均靠人工应答，容易漏回。*

### 痛点二：知识没有沉淀，全靠人工应答

产品知识、项目规则全在老员工脑子里，没有系统沉淀。新员工培训靠帮带，上手慢，客户问专业问题时回答不准确、不及时。

*产品型（古晶）：产品参数、选型知识靠老员工口传；项目型（乐式）：开发流程、售后规则、技术规格同样依赖个人经验，无法统一口径。*

### 痛点三：售后处理靠人随意发挥，小事容易失控

售后规则不清晰，员工处理方式不一致，执行结果全靠个人判断。

> 「古镇圈很喜欢吃瓜，一发马上爆圈。」——古晶光电张总

*产品型（古晶）：换不换货、怎么赔，不同员工给不同答案，引发抖音曝光；项目型（乐式）：系统调试和维保响应规则不统一，客户体验参差不齐。*

## 【第5页】产品长什么样

### 客户视角：怎么用

```
客户发消息
    ↓
AI引导客户说清楚需求（售前 / 售后 / 进度查询）
    ↓
知识库作答，覆盖产品参数、规格、项目流程、售后规则
    ↓
答不了 → 留资 + 通知对应人员跟进
    ↓
当日小结发给老板：哪些问了、哪些处理了、哪些还没跟
```

### 老板视角：得到什么

| 老板关心的事 | 知衍数字客服给的答案 |
|------------|-------------------|
| 客户发消息有没有人回 | 7×24小时响应，不漏单 |
| 员工售后处理有没有出格 | 规则由系统执行，员工无法随意发挥 |
| 今天发生了什么事 | 每天一条小结，主动推送 |
| 员工回答有没有统一口径 | 知识库统一规则，不依赖个人经验 |

### 覆盖三个阶段

- **售前**：产品咨询、参数查询、定制询盘引导、方案咨询、留资转销售
- **售后**：规则智能引导、投诉安抚、转人工处理
- **售中**：产品型——订单生产进度与交期查询；项目型——开发进度与配合事项查询（阶段一）、生产进度与交期查询（阶段二）。均需接外部系统，后期推进，可行性待评估。

## 【第6页】交付物与下一步

### 客户拿到的是什么

| 阶段 | 交付形态 | 说明 |
|------|---------|------|
| 第一阶段（Demo） | H5对话页，扫码即用 | 零安装，知衍负责后台维护和知识库更新 |
| 正式版 | 微信公众号入口，关注即用 | 按月订阅，客户无需任何技术投入 |
| 长期 | 独立小程序 / 嵌入OA/内部系统 / 桌面端 | 根据市场反馈和客户规模评估，OA嵌入需技术可行性确认 |

### 待三方讨论的问题

> 产品的最终载体是什么——公众号、独立小程序、还是桌面端安装包？
> 这直接影响定价方式和交付标准，建议结合市场反馈共同确定。

### 下一步时间线

- **现在**：用乐式现有数据完成知识库训练，跑通真实场景演示
- **4周内**：可对外演示完整流程
- **目标**：古晶光电试用，推动首个付费客户签约
- **后续**：视验证结果再向其他客户类型复制
