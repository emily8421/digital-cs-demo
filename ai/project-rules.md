## 1. Phase边界

> 当前阶段：**Phase1（MVP）**——能独立演示核心价值（群里消息有人接、该跟的已分给该跟的人、经营者收到小结）的最小连贯子集。
> 与 `docs/03-prd.md` §3 路线图一致（AI 建议·待确认）。

当前阶段：Phase1（MVP）

允许：
- 后端 Python + FastAPI（REST + Webhook 回调）
- 关系型数据库（PostgreSQL）持久化
- LLM + 向量检索（RAG）做单轮知识问答与留资/缺口判断
- 消息通道抽象层 + **内置模拟器**（用于脱离真实平台演示/测试）
- 转人工后「AI 暂停」编排（**会话级**：handed_off 后停止自动回复，解除后恢复）
- 非文字消息的**类型识别 + 群内如实告知 + 提醒人工**（不涉及内容理解）
- 定时任务（定时小结 / 日报）
- 内部管理 API（知识/留资/转交/路由/小结/会话状态的查询与配置）
- Docker 本地部署

禁止（本期不做，留待 P2 / 愿景）：
- 多轮对话状态机（定制询盘逐项引导）—— P2
- 售后质保边界推理 / 安抚话术生成 —— 愿景·待技术验证
- 转人工「AI 暂停」的**话题（thread）级**精化（P1 仅会话级）—— 后续
- 知识内容确认回写（写入需经拍板人确认）—— P2
- 语音 / 图片 / 视频**内容**理解（永久禁止；仅可识别类型并提醒人工，不可声称看懂）
- 订单 / 生产记录系统集成与「自动答进度」—— 愿景·待技术验证
- **企业微信客户群群内自动回复**（Sprint-0 已核实不成立）及**未选定替代通道前的任何真实通道接入**—— 愿景·待技术验证（见 `docs/sprint-0-wework-findings.md`）
- 任何对个人微信账号的非官方自动化操作（永久禁止）

下一阶段预告（Phase2 大致开放）：
- 定制询盘多轮引导、AI 身份披露、知识确认回写、响应时效 SLA 监控、转人工暂停的话题级精化；企业微信正式接入（验证通过后）。

## 5. 编码约定与禁区

> Phase 级功能禁止见 §1，技术栈替代品禁止见 §2，本节只管代码层。
> ⚠️ 本节为「待 03-09 审核后回填」的占位草稿；以下为建议默认，确认前不视为定稿。

### 5.1 既有约定（新代码必须向其看齐）
- 命名：后端 snake_case（含 DB 字段、函数、模块）；类 PascalCase；常量 UPPER_SNAKE。表前缀统一 `dcs_`。
- 分层与目录：`backend/` 建议 `api/`（接口层，仅进此层）→ `service/`（业务编排）→ `model/`（数据访问/领域模型）；通道接入归 `channels/`。
- 既有模式：消息处理统一走「通道适配 → 归一化消息 → 对话编排 → 出站」管线，新功能沿用，勿另起并行链路。
- 错误处理 / 日志：统一异常类型与统一日志格式（含会话 ID、发送方、消息类型）；待回填具体规范。

### 5.2 禁区（未经人工确认不得触碰）
- 不得擅改的文件 / 模块：通道适配层契约、路由规则默认数据、知识库种子数据、数据库迁移脚本。
- 不得擅自引入的依赖：**任何新依赖须先确认**（尤其 LLM/向量库/IM SDK 相关）。
- 不得自行实现的功能：见 §1「禁止」清单（多轮状态机、售后推理、知识回写、非文字内容理解、企业微信对外发送等）。
- 愿景 / 01 中的功能点不等于已批准实现；阶段归属以 `docs/03-prd.md` §3 路线图为准，编码以 §1 当前阶段为准。
